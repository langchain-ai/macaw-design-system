# Using the package

The package is ESM-only and supports React 18.2–19, TypeScript 5.4+, and modern
browsers (ES2022). React and React DOM are peers: the application must provide
matching versions. Tailwind is optional; its preset supports Tailwind 3.4.

## Styles and providers

Import `@langchain/design-system/styles.css` once in the app entry point. It
loads fonts, tokens, base rules, and compiled component utilities. Base rules
and Tailwind's reset apply globally, so review them when integrating into an
existing application. No source scanning is needed to style package components.

```tsx
import '@langchain/design-system/styles.css';
import { Button, TooltipProvider } from '@langchain/design-system';
import { AppThemeProvider } from '@langchain/design-system/hooks/AppThemeProvider';

export function App() {
  return (
    <AppThemeProvider defaultMode="system">
      <TooltipProvider>
        <Button>Continue</Button>
      </TooltipProvider>
    </AppThemeProvider>
  );
}
```

`TooltipProvider` is required for `Tooltip` and controls that show tooltips,
including labeled `IconButton` and `Avatar`. `ToastProvider` from
`@langchain/design-system/components/Toast` is required for toasts. The theme
provider updates `html.dark`, persists the selection, and supplies the theme
context used by code editors. Pass `storageKey={null}` to disable persistence.
If your app owns theming, supply `ColorSchemeContext.Provider` from
`hooks/useColorScheme` with the same resolved mode as the document's class.
Setting `html.dark` alone changes CSS but does not update that React context.

For a custom stylesheet, import `tokens.css` and provide your own base styles,
fonts, and utilities. The full `styles.css` is the supported zero-configuration
path. It already imports `tokens.css`; do not load both separately.

## Imports

Every component directory has an explicit entry point:

```tsx
import {
  Button,
  type ButtonProps,
} from '@langchain/design-system/components/Button';
import { BarChart } from '@langchain/design-system/components/BarChart';
import { Code } from '@langchain/design-system/components/Code';
import { CodeLite } from '@langchain/design-system/components/Code/CodeLite';
import {
  TabGroup,
  TabList,
  TabLabel,
} from '@langchain/design-system/components/Tabs';
```

The root also exports commonly used primitives (`Button`, `Card`, `Text`,
`Input`, and others); `src/components/index.ts` is the inventory. Prefer
component subpaths when controlling a bundle boundary. Charts, editors,
dialogs, and menus have their own dependency graphs. Tree shaking depends on
the application bundler; importing a subpath does not reduce installation size.

Hooks, contexts, icons, and utilities use the paths in `package.json#exports`.
Import named symbols; never reach into `dist/` or `src/`. Existing nested
component paths remain supported for compatibility, but the component's
`index.ts` is the preferred API. Runtime imports and declarations are checked
with both TypeScript Bundler and NodeNext resolution.

## Frameworks and server rendering

For a React Server Components framework such as Next.js, import interactive
components through your own `'use client'` component or providers file. Put the
global stylesheet in the framework's global CSS entry. The package does not
add client directives to every utility module. Ordinary server rendering of a
client component tree is supported; browser interactions run after hydration.

`Link` accepts native `href` or `as={<RouterLink to="/path" />}`. Routers,
authentication, and data clients are application dependencies. They are not
required to import or render package components.

## Tailwind

To author semantic utility classes in your app, add the preset and scan your
own source:

```js
// tailwind.config.cjs
module.exports = {
  content: ['./src/**/*.{js,ts,jsx,tsx,mdx}'],
  presets: [require('@langchain/design-system/tailwind-preset')],
};
```

Keep the stylesheet import. The preset supplies token names and plugins, not
CSS variables. Classes used only in your application are generated by your
application build. See [STYLES.md](STYLES.md) for the token reference.

## Local development

Use `pnpm build:watch` in this repo and link the package from your app as
described in the README. Ensure the app resolves one React instance when
linking (for Vite, `resolve.dedupe: ['react', 'react-dom']`). For a release-like
test, run `pnpm pack` and install the resulting tarball in a throwaway consumer.
The tarball includes built output, documentation, and licensing; it excludes
tests, stories, and build configuration.
